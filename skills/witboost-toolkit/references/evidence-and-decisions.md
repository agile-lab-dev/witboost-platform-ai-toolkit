# Evidence And Decisions

Prefer evidence in this order:

1. Executable behavior and public contracts.
2. Tests and validation scripts.
3. Locked decisions and architecture documents.
4. Configuration and deployment manifests.
5. General documentation and examples.

Report contradictions rather than silently selecting one source.

Persist decisions in the repository that owns the behavior. Record status, scope, evidence, compatibility impact, and open follow-ups. Never rewrite history when a decision changes; append a superseding decision.
